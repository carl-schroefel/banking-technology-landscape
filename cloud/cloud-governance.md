# ☁️ Cloud Governance in Banking

Cloud adoption in banking is not simply a question of moving workloads to Azure or AWS.

Financial institutions have to connect cloud architecture with security, identity, governance, operational resilience and regulatory requirements.

---

## 1. Landing Zones: Building the Foundation

A landing zone provides the governed foundation for cloud workloads.

Microsoft distinguishes between:

- **Platform Landing Zones** for shared capabilities such as governance, security and connectivity
- **Workload Landing Zones** where individual applications and workloads are deployed

For financial institutions, this becomes particularly relevant because governance controls need to be applied consistently across cloud environments.

**Key concepts:**  
`Landing Zones` `Azure Policy` `IAM` `Network Architecture` `Security` `Governance`

---

## 2. Security by Design

For financial institutions, cloud security cannot simply be added after deployment.

AWS describes **Security by Design** as an important principle for financial-services workloads, including standardized controls, encryption, access management and auditability.

**Key concepts:**  
`Encryption` `IAM` `Security Controls` `Auditability` `DevSecOps`

---

## 3. Where Regulation Meets Architecture

This is where cloud architecture in banking becomes particularly interesting.

DORA introduces requirements around **ICT third-party risk** when financial institutions depend on external ICT service providers for critical or important functions.

That connects regulatory questions directly with technical architecture:

**Cloud Provider**  
→ **ICT Third-Party Risk**  
→ **Governance**  
→ **Resilience**  
→ **Exit Strategy**

---

## 💡 My Takeaway

The interesting part of cloud in banking is not whether Azure or AWS can technically run a workload.

It is how **architecture, security, governance and regulation interact around that workload.**

That is the perspective I want to understand when speaking with technology organizations in banking.
